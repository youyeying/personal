# 数据库设计文档（个人记录系统）

> 版本：v2.1.0（v1.35.0 废除 user 表活动系数体系；v1.36.0 饮食三表 + user.diet_target_gap；v2.1.0 补全 development_session / feature_log / 饮食三表明细章节，与前/后端设计文档版本对齐）
> 数据库：personal\_record（MySQL，utf8mb4）
> 技术栈：Spring Boot 4.1 + MyBatis-Plus

***

## 1. 设计约定

- **命名**：表名 / 字段名统一小写下划线 `snake_case`；主键 `id`；审计 `created_at` / `updated_at`；软删除 `deleted`（0 否 / 1 是）

- **软删除**：全部业务表软删除，删除后保留历史数据；`mistake_keyword` 类关联表无软删除（本项目无此类表，全部软删除）

- **多用户**：业务表统一带 `user_id` 做数据隔离；一期仅一个初始用户（`user_id=1`），二期开放注册

- **唯一约束**：涉及软删除的唯一约束均带 `deleted` 字段，允许软删除后重建同名数据

- **金额**：一律 `DECIMAL(10,2)`，保留小数点后两位，禁止浮点类型

- **日期**：业务日期用 `DATE`（精确到天），审计时间用 `DATETIME`

- **索引**：高频查询字段建索引，常用组合条件建联合索引

### 3.10 auth\_session（认证会话表）✅（2026-08-25 建，2026-08-26 同设备复用改造）

| 字段                   | 类型           | 允许空 | 默认                 | 说明                                    |
| -------------------- | ------------ | --- | ------------------ | ------------------------------------- |
| id                   | BIGINT       | 否   | AUTO\_INCREMENT    | 主键                                    |
| user\_id             | BIGINT       | 否   | -                  | 所属用户                                  |
| refresh\_token\_hash | VARCHAR(64)  | 否   | -                  | refresh token 的 SHA-256 十六进制哈希（不存明文）  |
| expires\_at          | DATETIME     | 否   | -                  | refresh 过期时间（每次刷新滚动 +24h）             |
| device\_name         | VARCHAR(100) | 是   | NULL               | 设备名（浏览器 · 系统，仅展示用）                    |
| device\_key          | VARCHAR(64)  | 否   | ''                 | 设备指纹（UA 的 SHA-256），登录时按 用户+指纹 复用同设备会话 |
| created\_at          | DATETIME     | 否   | CURRENT\_TIMESTAMP | 创建时间                                  |
| updated\_at          | DATETIME     | 否   | ON UPDATE          | 更新时间                                  |
| deleted              | TINYINT      | 否   | 0                  | 软删除                                   |

索引：

- `PRIMARY KEY (id)`

- `uk_hash_deleted (refresh_token_hash, deleted)` 唯一：同哈希非删除仅一条，防同一 refresh token 重复存在

- `idx_user_id (user_id)`：登出/改密时按用户撤销会话

- `idx_user_devkey (user_id, device_key)`：登录时查同设备有效会话以复用

**认证机制说明（2026-08-25 双 token 改造）**：

- **accessToken**：JWT 短效（15 分钟），只存前端内存，不落 localStorage，防 XSS 读取。

- **refreshToken**：随机不透明串（32 字节 URL-safe base64），存 `httpOnly` Cookie（`SameSite=Lax`），本表只存其 SHA-256 哈希，防库泄露映射回明文。

- **滚动续期**：每次调 `/auth/refresh` 时 rotation 原地生新 token + 更新哈希 + 将 `expires_at` 滚动为当下 +24h；旧 token 立即失效。滚动 24h 内只要有过操作就自动续期，否则需重新登录。

- **多设备 / 同设备复用（2026-08-26）**：一个用户可多设备同时登录，每设备一行；同一设备（按 UA 指纹 `device_key`）反复登录时**复用**其未过期会话（原地换新 refresh token + 滚动过期时间），不再新增行；登录时顺带软删该用户已过期会话，防行堆积。

> 存量库执行建表：`database/schema.sql` 中 `auth_session` 建表语句。
> 存量库迁移（2026-08-26，同设备复用）：

> ALTER TABLE auth_session

>   ADD KEY idx_user_devkey (user_id, device_key);

**按动作类型使用的字段组合**：

- strength：weight(可空自重) + reps + **seconds（分钟+秒合并为总秒数，精确到秒；旧数据兼容 minutes）** + hand

- plank：seconds

- walk / cycling：distance + minutes（骑行 v1.34.0 复用该字段组合）

- stairs：floors + times + **seconds（分钟+秒合并为总秒数，手动填写，精确到秒；旧数据兼容 minutes）**

**消耗计算口径（前端 utils/exercise.ts，不落库，v1.29.0 速度→MET + 等效分钟双轨）**：

- 通用：净消耗(kcal) = (MET−1)×3.5×体重×分钟÷200；总消耗 = MET×3.5×体重×分钟÷200

- 力量/有氧计数：**速度 = 个数÷用时 → 速度比 = min(速度, max\_speed)÷ref\_speed → MET = 1+(baseMET−1)×速度比**（恒 ≥1 净消耗不为负）+ **等效分钟 = 个数÷ref\_speed**（总量由个数主导，用时不当乘子）

- 散步 MET 按速度定档（<3.2:2.8 / <4.0:3.0 / <4.8:3.5 / <5.6:4.3 / ≥5.6:5.0）

- 骑行 MET 按速度定档（Compendium 2024 道路骑行六档，v1.34.0 新增；<16.09:4.0 / <19.15:6.8 / <22.37:8.0 / <25.59:10.0 / <30.58:12.0 / ≥30.58:16.8，>50km/h 拦截）

- 爬楼梯：秒/层 = 总时长÷(层数×次数) → 分档 MET（≤11秒 8.8 / 11~16秒 7.0 / 16~22秒 5.5 / >22秒 4.2）；平板支撑：秒数 × baseMET 2.8

- **体重取「记录时的体重快照 body_weight」（v1.28.0）**，历史消耗固定不随当前体重变；无快照回退当前最新体重，绝不用目标体重

## 4. 文件存储设计

- 所有文件（头像、学习附件）存本地磁盘 `uploads/` 目录，数据库只存相对路径

- 目录结构：

  ```
  uploads/
  ├── avatar/            # 头像
  └── note/              # 学习附件（按 年/月/日 分目录）
  ```

- 文件名用 UUID 防重名；上传校验类型与大小（图片 ≤ 2MB）

- Spring Boot 静态资源映射将 `uploads/` 暴露为 `/uploads/**`，前端直接拼 URL 回显
